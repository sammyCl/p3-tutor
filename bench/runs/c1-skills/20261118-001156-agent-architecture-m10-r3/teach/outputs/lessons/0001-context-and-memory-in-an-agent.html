Warm-up 1 min

Recall

In the agent loop, who actually runs a tool such as "check the booking calendar": the model or your program? And is each trip around the loop one model call or a continuing one?

Check your answer

Your program runs the tool; the model only asks for it. Each trip around the loop is a separate model call. That second fact is the key to today: if every call is separate, something has to carry information from one call to the next.

What the model sees at every step 2 min

The context window is all the text the model can look at when it writes a response, including the response itself. It works like the model's working memory, and it is separate from the training data (Claude docs: context windows).

The model does not remember anything on its own. Your program sends the whole context again on every call: the system prompt, your tool definitions, every earlier message and every tool result. Each turn's input is all previous history plus the new message, so the context grows with each step (same page).

Think of a function with no global state: it only knows the arguments you pass in. The context is that argument.

Why a fuller window is not a better one 2 min

The window has a size limit, and current Claude models accept up to 1 million tokens, depending on the model (docs). A token is a chunk of text, roughly a word or part of one. Limits are not the only problem, though.

As the token count grows, the model recalls details less accurately. Anthropic calls this context rot and describes context as a finite "attention budget": each new token uses some of it (Anthropic: effective context engineering). The goal is the smallest set of useful tokens, not the largest.

Two ways to trim a long run:

  • Clearing: drop old tool results the agent no longer needs.
  • Compaction: summarize a nearly full context and continue from the summary. The art is choosing what to keep and what to discard (same article).
A common mix-up

"Bigger window, so just paste in all the manuals." It is tempting because the window is huge. But you pay for those tokens on every call, and recall gets worse as the window fills. A smaller, relevant context is cheaper and more accurate.

What survives between sessions 2 min

A new session starts with an empty context. If the assistant should know that a student finished the laser cutter training last week, that fact must be saved somewhere outside the context and loaded back in.

The simplest way is notes as memory: the agent writes facts to files or a database, and reads them back later. Anthropic's memory tool works this way. Claude asks to create, read or edit files under /memories, and your application runs each request on storage you control (Claude docs: memory tool). This is the same loop you already know: the memory is just another tool.

Two details matter for design:

  • Memory is only as good as what gets written. The agent saves what it judges useful, so a checklist or a clear rule helps.
  • Memory lives in your application, so you decide how long it is kept and who can read it. The docs also say to restrict file paths so one student's session cannot reach other files (same page).

Finding the right page in a long manual 1.5 min

Retrieval means fetching only the relevant piece of a large store and putting it in the context. Two timings exist (Anthropic article):

  • Up front: your code searches the manuals before the model call and adds the best matches. Fast, but the search runs once and may miss.
  • Just in time: the agent keeps light references, such as file names or search queries, and loads content with a tool when it needs it. Slower, but it can try again. Anthropic notes a hybrid is often best.

Summary 1 min

  • The model keeps nothing between calls; the context window is everything it sees, resent each step.
  • A fuller window costs more and recalls worse, so keep only what helps and trim the rest.
  • Between sessions, only what you save survives: notes or memory files your program stores.
  • Retrieval loads the few relevant pages instead of the whole manual.
