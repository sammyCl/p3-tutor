Warm-up 1 min

Recall

In the agent loop, the model asks for a tool call. Who actually runs the tool, and what happens to the result?

Check your answer

Your program runs the tool, not the model. The result is sent back to the model as new text, and the model is called again. Today's question is what that second call contains.

What the model sees on every call 2 min

The context window is all the text the model can use when it writes a response, including the response itself. Anthropic calls it the model's "working memory" (Claude docs). It is separate from what the model learned in training.

The model keeps nothing between calls. Each call, your program sends everything again: the instructions, the tool descriptions, the whole conversation so far and every tool result. Every turn is kept in full, and the response is added to the input for the next call (Claude docs).

In Python terms, the context is a list you grow and resend. The model never "remembers"; you re-show it.

Why a bigger pile costs more and works worse 2 min

Two things grow with the pile. The first is cost: every token in the context is input you pay for on every call, and a bar that grows each step is paid for again each step.

The second is quality. Accuracy and recall drop as the token count grows, an effect called context rot, so Anthropic's advice is to find "the smallest possible set of high-signal tokens" (Anthropic engineering).

When a long task fills the window, two fixes exist. Compaction summarizes the conversation and continues in a fresh window with the summary. Tool result clearing removes old tool outputs the agent no longer needs (same source).

A common mix-up

"A bigger window means I can paste in everything." It is tempting because windows now reach 1M tokens. But the window is a limit, not a target. A full window is slower to pay for and harder for the model to use well.

Check yourself

A request makes six tool calls. Each tool result adds 2,000 tokens. Why does the sixth model call cost more than the first?

Show the answer

The third option. Each call resends the whole context, so later calls carry more input.

Notes that outlive the session 2 min

When a session ends, its context is gone. For anything the assistant must know next time, such as "this student passed the laser cutter training on March 3", it has to be written somewhere outside the context and read back later.

That is structured note-taking: the agent "regularly writes notes persisted to memory outside of the context window" and pulls them back in when needed. Anthropic's examples are to-do lists and a NOTES.md file, which let Claude keep its place across thousands of steps while playing a game (Anthropic engineering).

You already know how: it is a file or a database row. Your program loads the student's record at session start and puts the relevant lines into the context. Memory is storage plus a decision about what to load.

This workspace works the same way: the tutor reads NOTES.md before each session because it does not remember the last one.

Fetching a page instead of carrying the manual 2 min

A machine manual may run to hundreds of pages. Putting all of it in every call would be expensive and would invite context rot. Instead, use retrieval: keep the manual outside the context, and load only the pages relevant to the question.

Anthropic describes agents that keep lightweight references, such as file paths or stored queries, and load content at runtime with tools, a style called just-in-time retrieval (Anthropic engineering). For you, a search_manual(machine, query) tool that returns the best two or three passages is one such tool.

Retrieval is how the assistant finds the right page. Notes are how it remembers a student. Both put a small amount of text into the context at the moment it is needed.

Worked example and your turn 3 min

Worked example

A returning student asks: "What laser cutter settings for 3 mm plywood, and book me Friday afternoon." Decide what goes where, one question at a time.

Step 1: what is always in the context?

Answer

The instructions and the tool descriptions, because the model needs them on every call. Keep them short; they are paid for each time.

Step 2: what do you load from memory at session start?

Answer

Only this student's training status for the laser cutter, a line or two. It decides whether booking is allowed. The rest of their history stays in storage.

Step 3: how does the manual get in?

Answer

The model calls search_manual. Only the matching passage on plywood settings comes back, not the whole manual.

Step 4: what happens to the calendar result?

Answer

It joins the context as a tool result. After the booking is made, a long list of open slots is no longer needed, so it is a candidate for clearing in a long session.

Step 5: what is saved at the end?

Answer

A note that the booking was made. The conversation itself is not kept; the note is.

Your turn

A student asks: "Can I use the 3D printer's heated bed with nylon?" Step 1 is given: the instructions and tools are in the context. Decide the rest: what do you load from memory, what do you retrieve, and what do you save afterward? Say why for each.

Show a solution

Memory: the student's 3D printer training status, to check they may use it. Retrieval: the manual passage on nylon and bed temperature, through search_manual. Save: nothing, or at most a note if the student's status changed, since an answered question is not worth storing.

Summary 1 min

  • The context window is everything the model reads on one call. It is resent in full each call and grows with every step.
  • A bigger context costs more and can work worse, so keep it to the smallest set of useful text.
  • Between sessions, only what you write to storage survives: notes.
  • Retrieval loads the relevant manual page on demand, instead of carrying the whole manual.
