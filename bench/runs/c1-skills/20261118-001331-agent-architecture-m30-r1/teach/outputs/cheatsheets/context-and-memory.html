Context and memory in an agent

From lesson 1. Sources: Context windows, Effective context engineering, Contextual Retrieval.

Terms

TermMeaning
Context windowAll text the model reads in one call, plus its reply: system prompt, tool definitions, messages, tool results.
TokenA word or word piece; the window and the bill are counted in tokens.
Context rotRecall and accuracy drop as the window fills.
Clearing / compactionDrop old tool results, or summarize and restart the window.
Notes (memory)Facts stored outside the model, loaded at the start of a session.
Retrieval (RAG)Search stored documents; put only the matching chunks in the context.

Rules of thumb

  • The model keeps nothing between calls; your code re-sends the history every step.
  • Big tool results are re-read, and re-paid for, in every later call.
  • Caching lowers price; cached tokens still fill the window.
  • Between sessions only stored notes survive. Save facts, not transcripts.
  • Permissions (who is trained) come from stored records written by your code.
  • Label every chunk with its machine and section.

Session recipe

  1. Load the student's record; put a short version in context.
  2. Retrieve only the chunks the question needs.
  3. Clear or summarize bulky results if the session runs long.
  4. Update the record only when a fact changed.
