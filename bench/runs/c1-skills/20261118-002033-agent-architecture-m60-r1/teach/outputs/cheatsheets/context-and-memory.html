Context and memory in an agent

Objective O3. Companion to lesson 1. Sources: Anthropic's posts on context engineering, context management and contextual retrieval.

Terms

TermMeaning
TokenA small chunk of text; the unit of window size and billing
Context windowThe most text the model can read and write in one call
ContextThe text actually sent on a call: system prompt, tool descriptions, transcript, loaded pages
TranscriptThe list of messages and tool results your program resends on every step
Context rotRecall gets worse as the window fills
CompactionSummarize a long conversation and continue from the summary
SessionOne conversation; its transcript is gone when it ends
MemoryStorage your code writes and reads outside the model and the window
Retrieval (RAG)Find the best-matching pieces of a big store and copy only those into the context
EmbeddingNumbers representing a chunk's meaning; used to search by meaning
BM25Keyword scoring; good at exact codes and names

Procedure: decide what goes where

  1. Needed on every call? Put it in the system prompt or tool descriptions, and keep it short.
  2. Needed only for this question and large? Retrieve it, then clear it when used.
  3. Needed next session? Save a short record, with a date if it can go stale.
  4. Already in a source of truth (calendar)? Read it live; do not copy it.
  5. Not needed again? Do not keep it.

Retrieval checklist

  • Under about 200,000 tokens (about 500 pages)? Pasting everything is possible; weigh the cost on every call.
  • Chunks of a few hundred tokens; start each with the machine name and section heading.
  • Hybrid search: meaning (embeddings) plus keywords (BM25).
  • Test with real questions: is the right chunk in the top few?
